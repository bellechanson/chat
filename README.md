# chat

스프링부트로 만든 실시간 웹 채팅입니다.
단체 채팅방과 1:1 대화가 있고, 메시지·읽음 표시·입력 중 표시 같은 건 새로고침 없이 바로 바뀝니다.

카톡이나 슬랙에서 당연하게 쓰던 기능들이 실제로는 어떻게 돌아가는지 궁금해서 만들기 시작했습니다.
처음엔 메시지만 주고받는 방 하나였는데 쓰다가 불편한 걸 하나씩 붙이다 보니 여기까지 왔네요.

## 사용한 것

- Java 17, Spring Boot 4.1 (Security, Data JPA, WebSocket)
- STOMP over WebSocket (Spring simple broker)
- Thymeleaf + 바닐라 JS (프론트 프레임워크는 안 썼습니다)
- Oracle 11g XE
- Gmail SMTP (가입할 때 이메일 인증)
- PWA (앱처럼 설치, 데스크톱 알림, 작업 표시줄 아이콘 숫자)

## 할 수 있는 것

**채팅방**
- 방 만들기 / 삭제, 방장이나 관리자가 강퇴
- 지금 방에 있는 사람 목록, "영희님이 입력 중" 표시 (사진을 올리는 중이면 "사진 12장을 보내는 중")
- 안 읽은 메시지 수, 날짜 구분선, 위로 올리면 이전 대화 더 불러오기

**1:1 대화**
- 상대가 안 읽은 메시지에 "1", 상대 접속 상태
- 대화방 나가기 (내 목록에서만 없어지고 상대한테는 알리지 않음)

**메시지**
- 수정, 삭제, 링크 자동 연결, 이모지 반응
- 답장, @멘션 (나를 부르거나 내 메시지에 답장하면 그 방 알림을 꺼 놨어도 알려 줌)
- 사진·파일 보내기 (Ctrl+V, 끌어다 놓기). 사진 여러 장은 한 메시지로 묶어서 보냄
- 사진 크게 보기, 이 대화의 사진만 모아보기
- 대화 안에서 검색 (Ctrl+F)
- 공지 고정

**그 외**
- 회원가입 이메일 인증, 아이디·비밀번호 찾기, 로그인 유지
- 방별 알림 끄기 (1시간 / 8시간 / 내일 아침까지 / 계속)
- 관리자 화면 (방 정리, 강퇴 해제, 회원 정지, 관리자 지정)
- 회원 탈퇴

웬만한 건 내 다른 탭이나 상대 화면에도 바로 반영되게 했습니다.
예를 들어 공지를 고정하면 방에 있는 사람들 화면 위에 바로 뜨고, 고정된 메시지를 누가 고치면 공지 글자도 같이 바뀝니다.

## 실행해 보기

필요한 것: JDK 17, Oracle XE(`localhost:1521/XE`), Gmail 앱 비밀번호

1. Oracle에 계정을 하나 만듭니다. 테이블은 처음 실행할 때 JPA가 알아서 만듭니다(`ddl-auto: update`).

2. 비밀번호를 설정 파일에 적어 두기 싫어서 환경 변수로 읽게 해 놨습니다.

   | 환경 변수 | 내용 |
   |---|---|
   | `CHAT_DB_USERNAME` | DB 계정 (없으면 `chatdb`) |
   | `CHAT_DB_PASSWORD` | DB 비밀번호 |
   | `CHAT_MAIL_USERNAME` | 인증 메일을 보낼 Gmail 주소 |
   | `CHAT_MAIL_PASSWORD` | Gmail 앱 비밀번호 (구글 계정 비밀번호 아님) |

3. 실행

   ```bash
   ./mvnw spring-boot:run      # Windows는 mvnw.cmd spring-boot:run
   ```

4. 브라우저에서 http://localhost:8081

올린 사진·파일은 `~/chat-uploads`에 저장됩니다.
처음엔 관리자가 없으니까 가입한 다음 DB에서 직접 바꿔 줘야 합니다. 그다음부터는 관리자 화면에서 지정할 수 있습니다.

```sql
UPDATE chat_user SET role = 'ADMIN' WHERE username = '내아이디';
COMMIT;
```

두 사람이 대화하는 걸 혼자 확인할 때는 `localhost:8081`과 `127.0.0.1:8081`을 각각 다른 창(하나는 시크릿 창)으로 열어서 다른 계정으로 로그인하면 편합니다.

## 만들면서 고민했던 것

**실시간 반영을 어디까지 할지**
기능을 하나 만들 때마다 "이게 바뀌면 누구 화면에서 뭐가 바뀌어야 하지?"부터 적어 보고 시작했습니다.
채팅방은 `/topic/room/{id}/...`로 방 사람 전체에게, 1:1은 `/user/queue/...`로 당사자 둘에게만 보냅니다.
같은 사람이 탭을 여러 개 열어 둔 경우(읽음 처리, 알림 끄기 설정 등)도 생각보다 신경 쓸 게 많았습니다.

**멘션을 닉네임으로 저장하면 안 되는 이유**
처음엔 "@영희"를 글자 그대로 저장했는데 영희가 닉네임을 바꾸면 다 깨졌습니다.
그래서 `<@회원번호>`로 저장하고 화면에 그릴 때 지금 이름을 붙이는 방식으로 바꿨습니다. 닉네임이 바뀌면 열려 있는 화면에도 바로 반영됩니다.

**기존 코드를 덜 건드리는 쪽으로**
공지 기능을 넣을 때 "고정된 메시지가 삭제되면?"을 처리하려고 삭제 코드마다 손을 대야 하나 했는데,
공지를 불러올 때 삭제된 메시지면 그냥 없는 걸로 치는 방식으로 하니까 삭제 쪽은 하나도 안 바꿔도 됐습니다.
공지 내용도 따로 복사해 두지 않고 매번 원래 메시지에서 읽어서, 수정·닉네임 변경이 자연스럽게 따라옵니다.

**사진 묶음**
사진을 30장씩 한 번에 보내다 보니 목록이 무거워져서 긴 쪽 640px짜리 썸네일을 따로 만들어 보여 주고 원본은 크게 볼 때만 불러옵니다.
Tomcat 11은 multipart 파트 개수 기본 제한이 50개라는 것도 이때 알았습니다.

**버전 때문에 막혔던 것들**
- Spring Boot 4는 Jackson 3를 쓰는데, 요청 JSON에 primitive 필드(`long`, `int`)가 빠져 있으면 바로 실패합니다. 요청용 record는 `Long`, `Integer`로 받게 바꿨습니다.
- Oracle 11g에는 boolean이 없어서 `NumericBooleanConverter`로 1/0을 씁니다. 컬럼을 나중에 추가하면 예전 행은 null이라 쿼리에서 `deleted is null or deleted = 0`처럼 같이 봐야 했습니다.
- Thymeleaf 3.1부터는 `th:data-*` 같은 데서 `${@빈이름...}` 호출이 막혀 있어서 컨트롤러에서 모델로 넘기는 식으로 바꿨습니다.

## 폴더 구조

```
src/main/java/com/green/chat
├─ config        WebSocket, Security, 구독 권한 검사
├─ controller    화면 / REST API / STOMP 메시지 처리
├─ service       비즈니스 로직, 실시간 알림 보내는 곳(RoomNotifier, DmNotifier)
├─ repository
├─ entity
├─ dto
├─ security      로그인 유지, 접속 세션 관리
└─ util

src/main/resources
├─ templates     Thymeleaf 화면 (fragments에 사이드바·입력칸 같은 공통 조각)
└─ static/js     화면 기능별로 나눔 (messages, search, gallery, pin, dialog ...)
```

## 아직 못 한 것

- 모바일 화면은 신경을 거의 못 썼습니다. PC 브라우저 기준입니다.
- 테스트 코드가 없습니다. 기능마다 직접 두 계정으로 눌러 보면서 확인했습니다.
- 데스크톱 알림이 처음 접속하면 꺼져 있어서 내 정보에서 직접 켜야 합니다.
- 서버에 올리지는 않았고 로컬에서만 돌려 봤습니다.
